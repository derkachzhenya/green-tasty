# Как вручную протестировать Green Tasty

Дата плана: 27 октября 2026. Найденные ошибки и ограничения: [отчёт](report-ru.md).

## Подготовка

Используйте тестовую среду и отдельные тестовые аккаунты. Удаление гостя и отмена брони меняют реальные данные: не используйте существующие клиентские заказы для этих проверок.

1. Откройте локальное приложение, обычно `http://localhost:8080`.
2. Подготовьте владельца A, другого клиента B и официанта W с доступом к выбранному ресторану. Назначение роли выполняет администратор; обычный клиент не должен назначать её себе.
3. Для W используйте другой профиль Chrome; гостевое приглашение открывайте в инкогнито. Так сессии не будут заменять друг друга.
4. Выберите свободный день через 2–3 дня, место и стол на 2 гостей. Время приложения — **Asia/Tbilisi**, которое может отличаться от времени компьютера в Киеве. Не копируйте старую дату из скриншота.
5. Для почтовых сценариев настройте тестовый почтовый ящик/перехватчик, где действительно доступны письма подтверждения и сброса пароля.
6. Держите DevTools → Console и Network открытыми. Перед отдельным сценарием очищайте журнал. При ошибке сохраняйте URL без токенов, шаги, ожидаемый/фактический результат, скриншот, код ответа и время.

Отмечайте каждый пункт: `PASS`, `FAIL`, `BLOCKED` или `N/A`. Ниже «ожидание» означает требование к корректной работе; известные расхождения помечены явно. Временный аудит-сервер 8097 после проверки выключен, его адрес и аккаунты не предназначены для дальнейшего использования.

## Короткий сквозной прогон — примерно 20–30 минут

1. Выйдите из аккаунта. Book a Table → выберите место, дату, 12:00 и 2 гостей → Find a Table → свободный слот → Sign In. После входа выбор должен сохраниться. Подтвердите бронь один раз.
2. В Reservations создайте персональное приглашение гостю и откройте его в инкогнито. Добавьте Strawberry 17.00 и Roasted 10.00. Корзина должна показать **27.00**. Отправьте выбор и обновите страницу.
3. Как владелец добавьте Spring 19.00 в количестве 2. Ваш итог **38.00**, групповой **65.00**. Сначала сохраните собственный выбор, затем отдельно отправьте группу ресторану.
4. Как W выберите дату брони. Откройте Submit Pre-order. Подтвердите Spring и Strawberry, отклоните Roasted. Публикация должна стать доступной только после решения по каждой строке. Подтверждённая сумма — **55.00**.
5. Как A обновите группу. Замените отклонённый Roasted на Avocado & Egg Toast 15.00. Как W подтвердите новую строку и опубликуйте результат.
6. Сверьте все три роли после reload: у владельца 38.00, у гостя **32.00**, общий подтверждённый итог **70.00**. Старые 10.00 допустимы только в истории. **Известная ошибка B01: сейчас гостю показываются 42.00 и старое блюдо как текущее.**
7. Создайте отдельную тестовую бронь для отмены. Как W смените стол, затем отмените бронь. После reload должны сохраниться новый стол и Cancelled.

Приведённые цены относятся к проверенному каталогу. Если каталог изменён, пересчитайте ожидания по актуальным ценам. Числа из макетов не используйте без проверки арифметики.

| P02 | Нажать Book a table и View menu в hero | Понятен путь к нужному месту/меню. Сейчас обе ссылки ведут к Locations — это промежуточный шаг. |

| P04 | Открыть каждый ресторан | Правильные адрес, фото и данные именно этого ресторана. Демо-статистика не выдаётся за фактическую. |
| P05 | Переключать категории и сортировку меню | Видны блюда выбранной категории; пустая категория объяснена; цена по возрастанию/убыванию сортируется численно. Сейчас новый каталог имеет пустые Main Courses/Desserts. |

## 2. Регистрация, вход и восстановление

Эта группа особенно важна: доставка настоящих писем в текущем аудите не проверялась.

| № | Действие | Что проверить |
| --- | --- | --- |
| A01 | Отправить пустую регистрацию | Понятные ошибки; аккаунт не создаётся. |
| A02 | Ввести неверный email, несовпадающие пароли и пароль вне показанных правил | Ошибки связаны с полями; секрет не появляется в URL/уведомлениях. |
| A03 | Зарегистрировать новый тестовый email | Одно создание, письмо приходит; до подтверждения доступ ограничен согласно правилам. |
| A04 | Ввести неверный/просроченный код, затем запросить новый | Неверный код не подтверждает аккаунт, повторная отправка соблюдает таймер; новый код работает. |
| A05 | Использовать уже зарегистрированный адрес | Нет второго аккаунта; понятный способ войти/восстановить доступ. |
| A06 | Вход: пустые поля, неверный пароль, затем правильный | Ошибки без входа; правильные данные открывают аккаунт. Выбор брони до входа сохраняется. |
| A07 | Несколько неверных входов | Ограничение попыток работает; сообщение объясняет ожидание. Использовать только свой тестовый аккаунт. |
| A08 | Forgot password → свой email → письмо → новый пароль | Ссылка/код работает, новый пароль подходит, старый больше не подходит. Повторно использованная ссылка не меняет пароль. |
| A09 | Выйти и нажать Back/открыть защищённый URL | Защищённые данные нельзя получить заново без входа. |

| B10 | Проверить ранние/поздние слоты | Доступность соответствует реальным часам работы. Сейчас 03:00 разрешено — расписание нужно определить. |

## 4. Приглашение и гостевой выбор

| G02 | Подтвердить имя, добавить 2 разных блюда | Верные блюда, количество и сумма; ничего из другой брони. |
| G03 | Изменять количество, удалять до пустой корзины | Суммы пересчитываются; пустая корзина объяснена; пустой гостевой выбор нельзя отправить. |
| G04 | Уйти/вернуться/reload до отправки | Сохранённый гостевой выбор соответствует фактическому состоянию; нет ложного успеха. |

## 5. Владелец и группа

| № | Действие | Что проверить |
| --- | --- | --- |
| O01 | Add Pre-Order → блюда → количество | Локальный расчёт корректен; Cancel Changes возвращает сохранённый выбор. |
| O02 | Сохранить свой выбор, открыть группу | Личный subtotal и сумма всех участников совпадают с расчётом. Личное сохранение не означает отправку ресторану. |
| O03 | Финально отправить группу с подтверждением | Успех только после ответа сервера; один заказ; после reload тот же статус. |
| O04 | Открыть две вкладки, изменить одну, сохранить старую | Старые данные не перезаписывают новые; понятный конфликт/предложение обновить. |
| O05 | Редактировать после финальной отправки/удалить подтвердившего гостя | Сейчас группа read-only; это намеренное ограничение реализации, отличающееся от некоторых макетов. Не считать свободное редактирование уже работающим. |
| O06 | Отменить будущую бронь как клиент | Сейчас клиентской кнопки нет — сценарий G01 из отчёта отсутствует. Проверить отдельно после реализации. |
| O07 | Отказ ресторана → разрешённая замена → повторная отправка | Старые подтверждения сохраняются; новая строка Pending; историческая строка исключена из текущей суммы. |

Для T01–T03 нужны управляемые тестовые часы/фикстуры на отдельной среде. Не меняйте системное время рабочего сервера и не правьте настоящие брони ради теста. В этом аудите браузером проверялись подготовленные состояния, точная граница дополнительно проверена автоматическими тестами.

## 8. Адаптивность, клавиатура и сбои

1. DevTools → Device Toolbar: 1440×900, 768×900, 390×844, 320×640. На каждом размере откройте главную, поиск, меню, корзину, группу и панель W. Проверьте отсутствие горизонтальной прокрутки, доступность нижних кнопок и внутреннюю прокрутку длинного окна.
2. Пройдите Tab/Shift+Tab. В открытом модальном окне фокус остаётся внутри; Escape закрывает и возвращает фокус на открывающую кнопку. Обязательные ошибки доступны клавиатурой.
3. Проверьте масштаб 200%: текст/кнопки не обрезаются; ошибка не обозначается одним цветом.
4. В отдельной тестовой сессии включите Network → Offline при сохранении. Не должно быть ложного «успешно». После восстановления сети проверьте сохранённое состояние и отсутствие дубля при повторе.
5. Проверьте медленную сеть: повторные клики не создают двойные брони/заказы; видно ожидание.
6. Повторите ключевой сквозной прогон в Safari/Firefox и на настоящем телефоне. Это ещё не покрыто текущим запуском.

```text
ID / название:
Среда, браузер, ширина:
Роль, ресторан, номер ТЕСТОВОЙ брони:
Предусловия:
Шаги 1–N:
Ожидалось:
Получилось:
Повторяется после reload: да / нет
HTTP-код и текст ошибки (без секретов):
Скриншот:
Приоритет: P1 блокирует сценарий/неверный итог; P2 важное неудобство; P3 косметика
```

Условия приёмки: B01 и B02 исправлены и повторно пройдены; обязательные продуктовые сценарии определены; почта подтверждена реальным тестом; нет двойных броней и доступа к чужим данным; итоговые суммы совпадают у всех ролей; известные пропуски явно приняты как ограничение версии.
