# Исправления после проверки трёх макетов

Исходные замечания сохранены в `step-01-home-restaurant-dish-ru.md`. Этот документ описывает результат исправлений, а не первоначальное состояние.

- Адреса трёх известных демо-ресторанов выровнены по макету без изменения идентификаторов и связанных записей. Seeder допускает локальное окружение только при явном включении флага; production запрещён.
- Цена карточки и окна блюда теперь берётся из одного источника, добавлен знак доллара. Используется известный вес из каталога; неизвестный вес Avocado не подменяется выдуманными 430 g. В макете Strawberry имеет противоречащие цены $17 и $15; приложение использует актуальные $17.
- В окне блюда восстановлены зелёная тема, шрифт и выделенные подписи пищевой ценности. Демонстрационные сведения обозначены видимо.
- По выбору пользователя отзывы остаются демонстрационными с видимой пометкой Demo. Категории имеют отдельные наборы, сортировка работает по дате и оценке, доступны три страницы по четыре отзыва и переход вперёд. Смена категории или сортировки возвращает на первую страницу.
- Book a table в баннере открывает поиск столов; View menu ведёт к выбору ресторана. Main page выделяется также на странице ресторана.
- Демонстрационные показатели столов, загрузки, атмосферы и рейтинга обозначены явно; отдельно показано число доступных для бронирования столов.

Проверено: 241 Vue-тест прошёл; TypeScript и форматирование/lint 155 файлов resources/js прошли; клиентская и SSR-сборки прошли. Ранее выполненные целевые PHP-тесты на SQLite: 37 тестов, 585 проверок; Pint изменённых PHP-файлов прошёл. В браузере проверены карточки, окно блюда, восстановленные адреса и меню; вторая страница отзывов меняет содержимое, переключение на Cuisine experience показывает другой набор и возвращает страницу 1.

PHPStan также прошёл без ошибок в последовательном режиме с лимитом памяти 512 MB. Обычный параллельный запуск был ограничен sandbox, поэтому использован режим --debug.

Полный повтор проверки бронирования и авторизации, мобильные размеры и попиксельное сравнение в этот этап не входят. После случайного migrate:fresh база отдельно восстановлена — подробности в `database-recovery-ru.md`.
