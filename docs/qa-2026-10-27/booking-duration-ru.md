# Выбор длительности бронирования — 27 октября 2026

Реализованы 1.5 / 2 / 2.5 / 3 часа в поиске, создании и редактировании брони, а также в интерфейсе сотрудника. Начало и длительность сохраняются отдельно; время окончания вычисляется из сохранённой записи. По умолчанию остаются два часа.

## Сохранность данных

Перед изменением рабочей базы создан полный SQL-бэкап в приватном, исключённом из Git каталоге `storage/app/private/duration-backup-2026-10-27/`. Миграция только добавляет `duration_minutes` со значением 120 для существующих записей. Таблицы и записи не пересоздавались.

Сразу после миграции сверены количества и хеши прежних полей 13 таблиц: изменений нет; все 14 существовавших бронирований сохранились с длительностью 120 минут. Результат записан в приватный `verification.json`. Последующие действия пользователя не входят в эту сверку.

Обратная миграция отказывается удалять колонку, если уже существуют брони другой длительности: иначе информация об их окончании была бы потеряна. Возврат к старому коду с фиксированными двумя часами после создания таких броней требует совместимого изменения расчётов; простое переключение кода не считается безопасным откатом.

## Проверки интервалов

Поиск и окончательное сохранение учитывают весь интервал выбранной и существующей брони. Конец одной брони может совпадать с началом следующей. После ожидания блокировки транзакция повторно проверяет доступность; два параллельных запроса не должны занять один стол на пересекающееся время.

Сохранённая длительность используется в статусах Upcoming / In Progress / Completed, меню владельца и гостя, карточках и интерфейсе сотрудника. Проверены интервалы через полночь. Для отправленного группового предзаказа сохраняется существующий запрет изменения брони. Сотрудник не может менять время начала или длительность уже начавшейся брони.

## Как проверить вручную

1. Обнови страницу приложения. В поиске выбери будущую дату, подходящий стол и 3 hours. Вместимость гостей ограничена выбранным столом и не зависит от длительности.
2. Выбери свободный слот, например 14:00. Review должен показать 14:00–17:00. После входа параметры должны сохраниться; Confirm создаёт одну бронь.
3. В Edit Reservation выбери 1.5 hours и сохрани. Ожидается 14:00–15:30; после обновления страницы тот же интервал и тот же reference.
4. Если продлеваемый интервал пересечёт следующую бронь, должно появиться сообщение об ошибке, а прежние данные должны сохраниться.

Даты и занятость рабочей базы могут отличаться. Для полного ручного сценария с подготовленными данными используй [чек-лист](booking-manual-checklist-ru.md); в нём контрольные времена рассчитаны для двух часов.
