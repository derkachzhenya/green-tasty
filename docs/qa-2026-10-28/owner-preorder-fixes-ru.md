# Предзаказы владельца: исправления и проверка

28 октября 2026 года. Реализованы пробелы, выявленные при сверке 27 изображений. Этот отчёт обновляет [аудит от 27 октября](../qa-2026-10-27/owner-preorder-audit-ru.md). Использованы приложенные макеты и открытый файл Figma; заметки внутри макетов рассматривались как материал для сравнения.

Изменения уже отправленной группы публикуются как новая версия для проверки рестораном сразу после успешного действия владельца. Повторная кнопка отправки всей группы остаётся отключённой. В личной корзине изменения отправляются только после Submit Pre-Order; Cancel Changes возвращает сохранённый вариант.

После удаления всех ранее отправленных блюд ресторан может подтвердить пустую новую версию. Исходная пустая группа по-прежнему не отправляется. Одновременные изменения сериализуются по брони; устаревшая версия получает конфликт вместо перезаписи более новых данных.

По ранее выбранному правилу T−30 **не удаляет блюда автоматически**. Поэтому текст об автоматической отмене через 15 минут из Figma заменён точным сообщением о закрытии изменений и сохранении блюд. Несогласованные примерные суммы в макете не копировались: приложение считает сохранённые цены и количества. Попиксельное совпадение всех кадров не заявляется.

## Проверено в Chrome

Проверка записей выполнена в отдельной SQLite-копии на 18086, без тестовых броней в рабочей MySQL и без изменения пользовательских броней на ручном стенде.

1. Отметка обновления видна до открытия группы и исчезает после загрузки актуальной версии.
2. Подтверждённый заказ $17 + $10 = $27. Изменение количества владельца 1 → 2 дало $44: $10 подтверждено, $34 ожидает проверки. Прежняя строка $17 осталась в истории.
3. Cancel в Remove Guest сохранил участника. Подтверждение удаления Alex дало $34; забронированных мест осталось четыре.
4. Добавление Spring Salad в личной корзине дало $53. До отправки база содержала только сохранённые $34. Cancel Changes вернул $34; последующий Submit сохранил $53 и показал подтверждение отправки ресторану.
5. После решения ресторана показаны $34 подтверждённых и $19 отклонённых. Замена Spring Salad на Avocado Pine Nut Bowl дала $51: $34 подтверждено, $17 ожидает проверки. Старое отклонение сохранено и исключено из текущих сумм.
6. Дополнительная корзина с уже подтверждённым первым выбором вызывает предупреждение. На T−30 окно сохраняет оба блюда и $27, не показывая действия изменения.
7. Keep Reservation ничего не отменяет. Cancel Reservation переместил тестовую бронь в Canceled: All 6, Upcoming 5, Canceled 1. Участники и позиции в базе сохранены.
8. Spring Salad показывает отдельный состав и приблизительное питание. На ширине 390 px модальное окно не имеет горизонтального переполнения, итог и кнопка доступны. Размер браузера после проверки восстановлен.
9. Обнаруженное при добавлении окна предупреждение Vue о наследовании атрибутов исправлено. После перезагрузки проверенного сценария новых предупреждений и ошибок консоли нет.

Сохранность исходных строк, текущий итог $51, пять снимков версий, данные отменённой брони и миграций зафиксированы в [persistence.json](owner-preorder-evidence/persistence.json).

## Ручной проход

Открой [Reservations рабочего приложения](http://localhost:8080/reservations). Для экспериментов используй прежний отдельный [ручной стенд 18081](http://localhost:18081/reservations).

1. Создай будущую бронь более чем за 45 минут, открой Add Pre-Order. Выбери блюда; проверь знак $, количество и итог.
2. Открой корзину, поменяй количество, нажми Cancel Changes: должен вернуться сохранённый выбор. Повтори и нажми Submit Pre-Order.
3. Пригласи гостя и открой его ссылку в инкогнито. После отправки гостем открой Reservations владельца: появится оранжевая отметка. Открой Group Pre-Order — отметка погаснет.
4. Отправь группу. Измени количество или личную корзину: появится Updated Pre-Order. Ресторан должен проверять актуальную версию; старые строки сохраняются.
5. Проверь Remove Guest: сначала Cancel, затем подтверждение. Гость исчезнет из текущего заказа, сумма уменьшится, число забронированных мест останется прежним.
6. При отклонении рестораном замени блюдо доступным: отклонение останется в истории, новая позиция будет ожидать решения.
7. Для брони за 31–45 минут с неподтверждёнными позициями проверь предупреждение. На 30 минутах до начала изменения должны закрыться; блюда остаются видны.
8. На тестовой карточке проверь Keep Reservation, затем Cancel Reservation и вкладку Canceled.
