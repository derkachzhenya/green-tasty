# Официант: брони, проверка предзаказа и обслуживание

Проверено 28 октября 2026 года по семи присланным экранам Figma.

## Реализовано

- Карточки Reserved, In Progress, Completed, Cancelled; фильтры даты, времени и столика, New Reservation, редактирование и смена столика. Дата ввода — `dd.mm.yyyy`, подписи карточек на английском. Навигация Reservations / Menu.
- Предзаказ: Created by Customer → решения по каждому блюду → Submit Pre-order → Confirmed by Restaurant / View Pre-order. Отправка недоступна, пока остаются блюда без решения. Отклонённые строки выделены, результат доступен владельцу через существующие уведомления приложения.
- Изменение клиентом: оранжевая отметка, Updated Pre-Order, новые блюда ожидают решения. Ранее опубликованные решения доступны только для чтения; заменённые строки и обе проверки остаются в истории. После публикации новой проверки отметка исчезает.
- Заказ во время визита: Create Order / Edit Order, меню доступных блюд, количество, заметки, удаление позиции, точный итог в долларах, Cancel Changes, Save Order. Подтверждённые блюда предзаказа включаются с историческими ценами и заметками. Перед работой с заказом нужно закончить проверку непроверенного клиентского предзаказа.
- Completed: View Order с сохранёнными блюдами и суммой, без редактирования. Cancelled: карточка без действий.
- Отмена будущей брони: Keep it ничего не меняет, Cancel закрывает бронь и показывает Reservation Cancelled! Предзаказы, решения и цены сохраняются в истории.
- Окна со скроллом содержимого и закреплёнными действиями, мобильная проверка при 390 px. Периодическое обновление карточек раз в 30 секунд, когда нет открытого окна.

## Границы данных

Заказ обслуживания хранится отдельно: `restaurant_service_orders` и неизменяемые снимки `restaurant_service_order_revisions`. Официант не перезаписывает предзаказ гостя. Цены новых блюд берутся с сервера; старые строки сохраняют свои цены. На клиенте деньги считаются целыми центами; сервер использует точную десятичную арифметику.

Записи требуют действующей роли waiter именно для этого ресторана, CSRF и актуального If-Match. Одновременные сохранения блокируются на строке брони; устаревшая версия получает 409. Переход в завершённое/отменённое состояние запрещает изменение заказа на сервере. Смена столика сохраняет время визита, включая секунды в старых записях.

Новый клиент без аккаунта через форму не создаётся: New Reservation использует существующий email. Уведомление владельцу — внутри приложения; email/SMS не отправлялись. Роль рабочего Booking Test не изменялась.

## Миграция и сохранность

Миграция только добавляет две таблицы, без `migrate:fresh` и повторного заполнения рабочих данных.

- Приватная копия MySQL: `storage/app/private/waiter-service-backup-2026-10-28/before.sql`; сверка прежних полей и строк — `verification.json`, `existing_data_unchanged: true`.
- Перед миграцией ручной SQLite 18081 сделана копия `/private/tmp/green-tasty-waiter-20261028/manual-before.sqlite`; все прежние строки 20 таблиц совпали после миграции.
- При первом применении MySQL выявил слишком длинное имя нового индекса. Имя сокращено; восстановлены только пустые новые таблицы незавершённой миграции. Старые таблицы не удалялись.
- Vite отдавал прежний кэш страницы. Сервер интерфейса перезапущен на хосте на 5174, Laravel остался на 8080. Для загрузки нового интерфейса обнови страницу браузера.

## Ручной проход

Для проверки подготовлен отдельный [стенд официанта](http://localhost:18087/staff/restaurants/1/reservations?date=2026-10-28&table=10). Его данные — SQLite-копия; рабочая база не используется. Тестовый вход: `waiter.acceptance@example.test`, пароль `WaiterQa2026!`. Данные входа предназначены только для этого локального стенда. Файл запуска и подготовки находится в `/private/tmp/green-tasty-waiter-20261028/`.

1. На дату 28.10.2026 выбери QA Table 21 и All times. Сверь кнопки по статусам. Alex Morgan после проверки перенесён на QA Table 22; там открывается Edit Order с $34.
2. Для Maria Parker нажми Edit Order: должны появиться подтверждённые блюда предзаказа с суммой $63. Измени количество и Cancel Changes — вернутся исходные значения. Save Order сохранит отдельный заказ обслуживания.
3. Для Julia Reed открой View Order: редактирования нет. У отменённых Daniel Walker и Inna Miller действий нет.
4. У Jasmine Smith открой View Pre-order: проверка опубликована, Spring Salad отклонён, прежняя версия блюда Julia доступна в Earlier replaced dishes.
5. На отдельной будущей брони владельца отправь/измени предзаказ. У официанта появится Submit Pre-order. Реши все новые строки и отправь; после обновления карточка вернётся к View Pre-order.
6. Создай будущую бронь на свободном столике для существующего email. Проверь пересечение времени и вместимость, затем Keep it / Cancel на этой тестовой брони.

Рабочий раздел: `/staff/restaurants/{id}/reservations`. Он доступен только уже назначенному официанту; обычная регистрация не выдаёт эту роль.
