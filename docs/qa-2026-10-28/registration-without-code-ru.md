# Регистрация без email-кода

По запросу владельца верхняя навигация больше не содержит **Staff area**. Вход официанта доступен через **Staff sign in** в окне **Sign In**, меню аккаунта и `/staff/login`.

Новый посетитель заполняет First Name, Last Name, Email, Password и Confirm New Password. После **Create an Account** аккаунт сразу активируется и выполняется вход. Если до регистрации был выбран столик, сохраняется возврат к бронированию; иначе открывается `/reservations`.

Email-код при новой регистрации не создаётся и не отправляется, очередь и SMTP для регистрации не требуются. В существующей схеме поле `email_verified_at` устанавливается сервером при создании аккаунта как автоматическое одобрение; это не подтверждение владения email по письму. Пользовательские поля роли не принимаются, доступ персонала не выдаётся.

Сохраняются проверка данных и уникальности email, хеширование пароля, CSRF, ограничение попыток и смена ID сеанса. Восстановление пароля и ранее начатые проверки email продолжают использовать отдельный существующий механизм кодов.

Проверено в браузере на изолированной копии: регистрация нового посетителя сразу открыла кабинет, форма кода не появлялась; у пользователя 0 staff-ролей и 0 auth-challenges. Рабочие аккаунты при ручной проверке не изменялись.

Проверки: SQLite — 548 пройдено, 28 пропущено; авторизация и интеграционные сценарии на MySQL — 91 пройдено, 1 пропущен; интерфейс — 270 пройдено. TypeScript, PHPStan, Pint, lint, форматирование и сборка клиента + SSR без ошибок.
